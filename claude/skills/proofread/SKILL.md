# Proofread

書いている最中には「書き終えたら見直す」型の規則を思い出せないので、書き終えた文面を照合表に当て、確定の前に違反を直す。

照合表に載せたのは、語の検索か、その文面だけを見て文ごとに「はい / いいえ」で答えられる問いで見つけられる規則だけ。

## 照合する文面

- CLAUDE.md の指示でモデルが起動したときは、書き終えた文面
  - まだユーザーに示していない文面なので、そのまま直す
- ユーザーが `/proofread` を打って起動したときは、引数で渡されたファイルか、引数がなければ直前に書いた文面
  - 引数の有無を問わず、文面を直さず、当たった箇所と修正案 (現在の表現 → 変更後の表現) を示して止める。ユーザーが手で起動するのは、示した文面や手直ししている成果物を見た後のことが多く、CLAUDE.md の「変更の示し方」が、同意を得てから編集すると定めているため
- 文書の差分では、足した行と書き換えた行だけを照合し、変更のない行に当たっても直さない。変更のない文を書き換えると、CLAUDE.md の「変更の示し方」の規則に反し、差分も広がるため

## 読む回数

- 1 セッションで 1 回読めばよい。照合表は文脈に残るので、会話が要約された後を除き、次の文面からは起動し直さずに照合する

## 進め方

1. 照合表の行ごとに、照合する文面が「当てる文面」の種類に当たるかを見て、当たらない行は飛ばす。人間向けの文章に限る規則を当たらない文面に当てると、不要な書き換えになるため
2. 「検索に使う式」の正規表現で検索し、当たった行を出す。自分が書いた文は、読み返しても違反に気づきにくいため
   - Bash で `rg -n -o -e '<式>' <ファイルのパス>` を実行する。当たった語だけが行番号付きで出るので、どの語に当たったかを目で探さずに済む
   - 読点で区切った文字列の語は正規表現の特殊文字を含まないので、正規表現のまま検索してよい
   - ファイルにない文面 (示す前のコミットメッセージ案など) は、スクラッチパッドに書き出してから検索する
   - 文書の差分は、足した行と書き換えた行をスクラッチパッドに書き出してから検索する。`git diff` の出力をそのまま検索すると、行頭の `+` のせいで行頭に合わせる式が当たらないため
   - 当たった語から、照合表のどの行の違反候補かを引く
3. 問いは文ごとに当てる。段落をまとめて読むと、1 文だけの違反を見落とすため
4. 当たった箇所は、規則の本文を確かめてから直す
   - CLAUDE.md の見出しを指す行は、その節の本文を読み直す。検索する語は違反の候補を拾うだけで、例外 (コードの中や、規則が定める署名など) は本文に書いてあるため
   - 規則の欄に文で書いた規則は、その文も本文として扱う。照合表だけに載せた規則と、CLAUDE.md の規則にまとめた規則がこれに当たる
   - 直すと文が読みにくくなるときは、まず別の言い方に組み替える。組み替えても読みにくくなるなら直さずに残し、残した箇所と理由を、文面を示すときにユーザーへ伝える。検索する語は違反の候補を広めに拾うので、規則に機械的に合わせると不自然な文になる箇所があるため
5. 直した文だけに、もう一度照合表を当てる。直すときに、括弧の補足や名詞止めのような別の違反が入ることがあるため
6. 1 行を親と子の項目に分けた箇所ごとに、子の行を消すと親の行の主張が変わるかを見て、変わるなら直す前の 1 文に戻す。条件や中身を子に移すと、親の行だけでは範囲や何をしたかが読めなくなるため
   - 主張が変わるのは、条件が消えて範囲が広がるときと、中身が消えて何をしたかが分からなくなるとき
   - 直す前の行と比べて決めるので、親の行を「一部の〜」のようにぼかして読めるようにしても、戻す
   - 戻した行は、60 文字を超えていても分け直さない

## 当てる文面の種類

- 全部: コードとインラインコードの中を除く、すべての文面
- 人間向け: CLAUDE.md の「組み立て」が定める人間向けの文章。AI 向けの文脈情報 (`<details>` の中身) と、AI への指示文 (CLAUDE.md、AGENTS.md、SKILL.md) は除く。AI への指示文は、規則と理由を 1 項目に書き切る形で書かれていて、1 文 1 行の箇条書きに直すと規則と理由が離れるため
- 他者向け: CLAUDE.md の「他者に出す資料に書かないこと」の冒頭が定める資料と、コミットメッセージ
- ほかの種類は、欄に書いた文面だけに当てる

## 照合表

### CLAUDE.md に本文がある規則

規則の欄は、CLAUDE.md の「文章の書き方」の小見出しと、その中の規則を指す。

| 規則 | 検索する語・問い | 当てる文面 |
| --- | --- | --- |
| 「文字と記法の規則」の丸括弧 | （、） | 全部 |
| 「文字と記法の規則」のコードブロックの言語 | `` ^\s*``` `` (当たった行を上から数え、奇数番目の開きのフェンスに言語がないかを見る) | Markdown |
| 「語の選び方」の、英単語に活用語尾や助詞を直結させる型 | `[a-z] [しすさせな]`、`[a-z] でき` | 全部 |
| 「語の選び方」の exit code の書き方 | 非 0、非ゼロ、`\bpass(ed)?\b` | 全部 |
| 「語の選び方」の英語 3 語以上の羅列 | `[A-Za-z]+ [A-Za-z]+ [A-Za-z]+` (固有名詞は除く) | 全部 |
| 「語の選び方」の比喩・成句 | 問い: 字義どおりに読むと意味が通らない比喩や成句があるか | 全部 |
| 「語の選び方」の、主語・目的語・条件を書き切る規則。あわせて、受け身で動作の主体を落とさない | 問い: 省いた主語・目的語を、前後の文から 1 つに決められるか。受け身や省略で、何の判断・何の作業の話かが読み取れなくなっていないか<br>語: され | 全部 |
| 「語の選び方」の指示語。あわせて、指示語で節全体や前のターンを指さない | 語: これ、それ (「おそれ」は除く)、この、その、上記、前述、先ほど<br>問い: 指す先が、直前の文か同じ項目の中の語で 1 つに決まるか | 全部 |
| 「組み立て」の、理由を名詞止めで書かない規則 | 語: 理由、目的、狙い、ことです、ためです、からです、ことにある、ためである、`のは、`、`(ため/こと/から)だ` の後に句読点か行末、`^[^。]*ため。?$` (理由だけで終わる行。前の文で動作を書いた後の添え書きは対象外)<br>問い: 理由や目的を述べる文が、動作の主語と「〜なので、〜する」の向きを書いているか | 全部 |
| 「組み立て」の、決め手になった理由だけを書く規則 | 問い: 1 つの判断に理由を 2 つ以上並べていて、そのどれかが、ほかの候補を選んだ場合にも同じように言えるか | 全部 |
| 「組み立て」の「項目: 内容」の形 | `^\s*[-*] [^:：]{1,20}[:：][^/]` | 人間向け |
| 「組み立て」の、3 つ以上の網羅の列挙 | 語: ・<br>問い: 読点か中黒で 3 つ以上の要素を並べた網羅の列挙か | 人間向け |
| 「組み立て」の、番号だけで別の文書の箇所を指す型 | `論点 ?[0-9]`、`節 ?[0-9]`、`No\. ?[0-9]`、`項目 ?[0-9]` | 全部 |
| 「組み立て」の issue / PR の番号 | `#[0-9]` | 全部 |
| 「組み立て」の 1 文 1 行の箇条書き | 語: `^.{61,}$`<br>問い: 1 行に 2 文以上が入っているか | 人間向け |
| 「組み立て」の括弧書きの補足 | `\(` | 人間向け |
| 「他者に出す資料に書かないこと」の会話の経緯 | 当初、訂正、回目、前回、以前は、指摘を受け、稿目、`第 ?[0-9]+ ?稿` | 他者向け |
| 「他者に出す資料に書かないこと」の、会話でしか通じない付番 | `PR-[0-9]`、フェーズ、ステップ、残りの | PR のタイトルと本文、コミットメッセージ |
| 「他者に出す資料に書かないこと」のローカル環境の情報 | /Users/、~/、/tmp/、/private/ | 他者向け |

### 照合表だけに載せる規則

規則の欄の文が、その規則の本文になる。

| 規則 | 検索する語・問い | 当てる文面 |
| --- | --- | --- |
| 出どころを「一般的に」「社内の」のような語でぼかさず、リポジトリ名・文書名・リンクで示す | 一般的に、一般に、社内の、とされ、と言われ、よく知られ、多くの、ベストプラクティス | 全部 |
| 意味を足さない言い回しで文を水増しせず、短い言い方にする | することができ、を行う、を行い、を実施、という形で、となっております、において、に関して、的な | 全部 |
| 大げさな語や AI が好む語で飾らず、何がどうなるかを具体的に書く | 重要な役割、として機能、を担う、を実現、シームレス、堅牢、包括的、多岐にわたる、強力な、鍵となる、不可欠、効果的 | 全部 |
| 程度や様子の副詞で動詞を補わず、動詞そのものか事実で言う | しっかり、きちんと、適切に、確実に、大幅に、非常に、とても、かなり、十分に、スムーズに、柔軟に | 全部 |
| 文中の語を太字で強調せず、文の組み立てで示す | `\*\*`、`__` | Markdown |
| 装飾の絵文字を使わない。規則が定める署名の絵文字は除く | `\p{Emoji_Presentation}`、`\x{FE0F}` | 全部 |
| 「だけ」「ない」の位置や「A と B の C」の形で、係り先が 2 通りに読める文を書かない | 語: だけ、のみ、しか<br>問い: 修飾語の係り先と、「A と B の C」の C がどこまで係るかが 1 通りに決まるか | 全部 |
| 漢語の名詞を 3 つ以上つながず、助詞か動詞を入れてほどく | `\p{Han}{6,}` | 全部 |

# 今日の作業の切り上げ

翌日の自分 (別セッションの AI) が、この会話を読まずに作業を再開できる状態にする。会話は要約や再開の過程で詳細が落ちるので、再開に必要な情報は memory に書き出す。

## ワークフロー

### 1. 現状を整理する

この会話を振り返り、次の 4 点を洗い出す。

- 確定したこと: ユーザーと合意した決定事項、完了した作業
- 未着手・途中のこと: 残っている作業と、途中の作業がどこまで進んでいるか
- 次の具体アクション: 再開したら最初にやること 1 つ
- 関連する場所: ブランチ名、PR / issue の URL、作業中のファイル、仕様ドラフトなどのドキュメント

git 管理下で作業していた場合は `git status --short --branch` を実行し、未コミットの変更があればブランチ名とあわせて記録する。コミットやプッシュはこのスキルの範囲外なので、指示がない限り実行しない。

### 2. memory に保存する

`project` タイプの memory として保存する。

- 同じ作業についての memory が既にあれば、新しく作らずにそのファイルを更新する。古くなった記述は消す
- 日付は「今日」「明日」と書かず、絶対日付で書く (例: 2026-10-02 時点)
- 確認した事実と推測を分けて書く。確認していない項目は「未確認」と明記する

### 3. 次セッションでの指示例を提示する

翌日そのまま貼れる指示を、コードブロックで 1 つ提示する。CLAUDE.md の再開時の規則 (あらすじを返す) が働くよう、「〇〇の作業を再開します」で始める。

```text
<作業名> の作業を再開します。<次の具体アクション> から始めたいです。
```

## 報告の形

次の 3 つを短く書く。報告のみにして、質問や「他に残すことはありますか」のような確認を付けない。

1. 保存した memory のファイル名と、確定したこと・未着手のことの要約 (各 1〜3 行)
2. 未コミットの変更がある場合はその旨とブランチ名
3. 次セッションでの指示例
